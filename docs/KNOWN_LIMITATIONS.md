# V1.0.0 已知限制

这份代码的目标是“可运行、架构闭环、可继续开发”，以下能力暂未伪装成已完成。

## 1. AI 分类是启发式

没有附带视觉模型。

因此：

- 普通 IMG_1234.JPG 无法知道里面是不是拉面
- “旅行 / 美食 / 宠物”只有文件名有相关词时才可能分类
- Screenshot 可通过文件名与长宽比得到较高识别率

## 2. 图片大小是估算

`estimatedBytes` 使用像素估算。

原因：首次索引对 5000 张逐个获取 AssetInfo 会明显拖慢体验。

正式版应后台读取真实文件大小。

## 3. 相似照片不是视觉相似

当前规则：

- 拍摄时间 <= 5 秒
- 尺寸接近

适合识别部分连拍，但不是 pHash。

## 4. 搜索不是 CLIP

当前支持：

- 分类关键词
- 中文同义词映射
- 今年 / 去年

“海边的猫”需要真实图像 Embedding 后才能准确。

## 5. 演示图片来自网络

Demo 使用 picsum.photos，仅用于无系统照片的模拟器 UI 预览。

真实照片模式不依赖网络。

## 6. SQLite 当前最多加载 5000 条进 Store

数据库和 Store 当前最多处理 5000 条，照片网格和回收站使用虚拟列表。

超过 5000 条时，正式版相册网格应改为 DB Cursor Pagination。

## 7. 系统照片同步

完整扫描结束后会清理系统相册中已不存在的旧索引；达到 5000 条上限而提前停止时不会清理，以避免误删未扫描到的索引。

## 8. 设置开关

设置保存在本地 settings 表。本地 AI、自动分类会在下次扫描时生效；搜索索引关闭后不会显示搜索结果。
